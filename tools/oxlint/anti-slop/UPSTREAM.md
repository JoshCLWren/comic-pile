## Intentional deviations

- **Effect plugin not registered.** This project has no direct `effect`
  dependency, so only the generic plugin is enabled.
- **Oxlint default categories disabled** (`categories.correctness = "off"` in
  `.oxlintrc.json`). This install is a focused anti-slop gate; it deliberately
  does not run Oxlint's built-in rule set alongside the existing ESLint config.
  Only the anti-slop rules plus the companion `oxc/no-accumulating-spread` are
  enabled.
- **Scope: `frontend/` only.** The TypeScript/React source lives under
  `frontend/`; the plugin is not run against Python or legacy `static/js`.
- **`frontend/src/generated/**` ignored.** `openapi.ts` is auto-generated by
  `openapi-typescript` ("Do not make direct changes"); linting or hand-editing
  generated output is incorrect.

## Enforcement — per-rule ratchet

Rules are enabled one category at a time. A rule is enforced repo-wide
(`"error"` in `.oxlintrc.json`) only once its entire backlog has been driven to
zero; until then it is staged `"off"`. CI runs the full-repo gate
(`pnpm run lint:anti-slop`, wired into the "Frontend Lint + Typecheck" job in
`.github/workflows/ci.yml`), which fails on any enforced rule. Because staged
rules are `"off"`, `main` stays green while their backlogs exist.

Each staged rule is owned by a GitHub issue (label `code-debt` + `ralph-task`)
that:

1. fixes every finding for that one rule across `frontend/`,
2. flips the rule from `"off"` to `"error"` in `.oxlintrc.json` in the same PR,
3. leaves `pnpm run lint:anti-slop` green.

To measure a staged rule's backlog, temporarily set it to `"error"` in
`.oxlintrc.json` and run `pnpm run lint:anti-slop` (the CLI `-D` flag does not
override a config `"off"`, and the config must stay at the repo root so the
vendored plugin path resolves).
