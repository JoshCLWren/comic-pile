# Comic Pile API documentation

## Overview

ComicPile's API is a same-origin HTTP/JSON surface served by native Rust. The
browser client uses the `/api` prefix; local development can also address the
standalone service directly.

- **Browser base URL**: same-origin `/api` (locally `http://localhost:5173/api`).
- **Standalone local service**: `http://127.0.0.1:8010`.
- **Content type**: `application/json`.
- **Authentication**: bearer access token plus refresh cookie and CSRF flow.
- **Production ingress**: every `/api/*` request is handled by native Rust;
  unknown API paths return a Rust JSON 404.

There is no deployed FastAPI application, Python reverse proxy, Swagger UI,
ReDoc page or runtime `/openapi.json` endpoint.

## Sources of truth

Use these generated and code-coupled sources instead of a hand-maintained route
table:

1. `native/roll-service/src/lib.rs` — the actual Axum route registry.
2. `native/contracts/v2-runtime.openapi.json` — canonical native v2 contract.
3. `native/contracts/same-path-runtime.openapi.json` — native operations that
   intentionally retain v1 or unversioned method/path contracts.
4. `frontend/src/generated/openapi.json` and `openapi.ts` — merged client
   contract regenerated by the repository scripts.
5. `frontend/src/services/` — actual first-party callers.
6. `docs/api/v2-route-inventory.json` — generated v2 cutover inventory. Its
   `full_surface` section is not an exhaustive registry of native v1
   compatibility routes.

See [native contract generation](../native/contracts/README.md) and
[frontend OpenAPI types](FRONTEND_OPENAPI_TYPES.md).

## Versioning and runtime

- Add new client resources under `/api/v2/*`.
- Retained v1 and unversioned operations run in native Rust only where the route
  registry and same-path generated contract still publish them.
- A URL's `v1`/`v2` segment identifies a contract version, not an implementation
  language. Do not infer runtime from the path.
- Do not redirect a retained v1 operation to v2 merely to reach a different
  implementation. A URL change is a separate API decision.

Auth publishes the same handlers under `/api/v2/auth/*`, `/api/v1/auth/*` and
`/api/auth/*`; product clients use v2. Other compatibility paths remain only for
existing callers documented in the same-path contract.

### Retired or absent surfaces

- `POST /api/v1/roll/` and `POST /api/roll/` are retired. Roll mutations use the
  v2 resources above.
- `POST /api/v1/rate/` and `POST /api/rate/` are retired. The native issue update
  path is `PATCH /api/v2/issues/{issue_id}`.
- `GET /api/v1/sessions/`, `GET /api/v1/sessions/{id}` and their unversioned
  aliases are retired. Use the v2 reading-session details/snapshots resources.
- `GET /api/v1/analytics/metrics` and `GET /api/v2/analytics/metrics` are not
  registered. The frontend `/analytics` route redirects to `/`.
- Admin JSON import/export endpoints are absent. Database backup and restore are
  operator procedures in [DATABASE_SAVE_LOAD.md](DATABASE_SAVE_LOAD.md).
- The former `/docs`, `/redoc`, `/openapi.json` and bare `/health` URLs return
  404 at Vercel ingress.

## Reading List and Roll behavior

Reading Lists are the canonical reader-owned sequence. Natural issue position,
strict/loose list mode, list-local gates and explicitly reader-authored
prerequisites determine eligibility. Historical/converted dependency rows are
audit evidence, not execution authority. See
[READING_LIST_RUNTIME.md](READING_LIST_RUNTIME.md) for modes, overlap decisions,
exclusions and the owner's single-engine correction. The obsolete
`OPTION_E_ENABLED` / `OPTION_E_APPROVED_PREVIEW` gate is an implementation
discrepancy, not supported configuration.

Roll is sessionless at the product boundary. `GET /api/v2/roll/bootstrap` is the
read projection; `POST /api/v2/reading-sessions` initializes durable history when
required. Direct manual Read/Rate uses
`PATCH /api/v2/issues/{issue_id}` with `source: "direct"`; it is not an
eligibility-gated pending Roll selection. `POST /api/v2/roll/override` remains a
specialized Roll-offer operation. Do not reintroduce a Python session or rate
endpoint from an old example.

## Errors and ownership

- Validation failures use the generated operation's documented status and JSON
  `detail` body.
- Missing and foreign-owned resources return `404` without confirming that
  another reader's resource exists.
- Authentication failures return `401`; CSRF failures follow the auth contract.
- Database transport failures return `503` with `Retry-After: 30` and an
  `error.code=database_unavailable` envelope rather than raw driver details.
- Request timeouts return a sanitized `503` detail body.

Never log or return credentials, SQL, reset tokens, provider secrets or raw
upstream error payloads.

## Configuration

The standalone native process reads `RUST_ROLL_DATABASE_URL`,
`RUST_ROLL_JWT_SECRET`, `RUST_ROLL_ENV`, `RUST_ROLL_BIND` and pool/timeout
settings. The Vercel entrypoint also accepts `DATABASE_URL` / `SECRET_KEY` and
normalizes supported driver URL forms. The obsolete Reading List rollout variables
are not supported configuration.
See [the native service README](../native/roll-service/README.md) for the exact
configuration table.

`CORS_ORIGINS` and `SESSION_GAP_HOURS` are not read by the current native config.
Do not document them as active native controls. The dice ladder is
`[2, 4, 6, 8, 10, 12, 20]`; native Roll rating steps use the 4.0 threshold.

## Regeneration and validation

```sh
cargo run --locked -p comicpile-roll-service --example v2_openapi \
  > native/contracts/v2-runtime.openapi.json
cargo run --locked -p comicpile-roll-service --example same_path_openapi \
  > native/contracts/same-path-runtime.openapi.json
node scripts/export_openapi_schema.mjs
node scripts/generate_openapi_types.mjs
node scripts/generate_openapi_types.mjs --check
```

Rust drift tests and frontend CI verify the checked-in generated artifacts. Do
not edit generated JSON or TypeScript directly.

## Known reconciliation gaps

These are recorded discrepancies, not supported API guidance:

- The generated same-path contract currently includes
  `GET /api/v1/issues/{issue_id}/dependencies`, but the native router mounts the
  live read at `GET /api/v2/issues/{issue_id}/dependencies`. The frontend uses
  v2. The stale generated alias requires a separate contract repair.
- `frontend/src/services/api-sessions.ts` still references the retired v1
  session list/get paths even though the router retains only v2 details and
  snapshots. This caller drift requires a separate focused repair.
- Checked-in `vercel.json` still contains generated references to the removed
  `api/native_issue.rs` function. <!-- docs-path-check: ignore --> The production workflow regenerates routes and
  then strips the retired function; route artifacts are bot-owned and must be
  regenerated through that workflow, not hand-edited in a documentation PR.
