# Comic Pile API documentation

## Overview

ComicPile's API is a same-origin HTTP/JSON surface served by native Rust. The
browser client uses the `/api` prefix; local development can also address the
standalone service directly.

- **Browser base URL:** same-origin `/api` (locally `http://localhost:5173/api`).
- **Standalone local service:** `http://127.0.0.1:8010`.
- **Content type:** `application/json`.
- **Authentication:** bearer access token, HttpOnly refresh cookie, and a
  double-submit CSRF cookie/header for authenticated state-changing requests.
- **Production ingress:** the deploy workflow generates Rust-only ingress for
  `/api/*`; unknown API paths return a Rust JSON 404.

There is no deployed FastAPI application, Python reverse proxy, Swagger UI,
ReDoc page, or runtime `/openapi.json` endpoint.

## Sources of truth

Use these generated and code-coupled sources instead of a hand-maintained route
table:

1. `native/roll-service/src/lib.rs` and `api/native_roll.rs` — the actual Axum
   route registries and Vercel entrypoint.
2. `native/contracts/v2-runtime.openapi.json` — the native runtime contract.
3. `native/contracts/same-path-runtime.openapi.json` — native operations that
   intentionally retain v1 or unversioned method/path contracts.
4. `native/contracts/python-legacy.openapi.json` — a frozen schema input for
   legacy compatibility DTOs; it is not a live Python handler.
5. `frontend/src/generated/openapi.json` and `openapi.ts` — the merged client
   contract regenerated by the repository scripts.
6. `frontend/src/services/` — actual first-party callers.
7. `docs/api/v2-route-inventory.json` — the generated v2 runtime/caller
   inventory. Its `full_surface` section covers the cutover inventory, not every
   native compatibility route.

See [native contract generation](../native/contracts/README.md) and
[frontend OpenAPI types](FRONTEND_OPENAPI_TYPES.md). When narrative and generated
contracts disagree, treat the mismatch as a defect to repair, not permission to
invent a route.

## Versioning and runtime

- Add new client resources under `/api/v2/*`.
- Retained v1 and unversioned operations run in native Rust only where the route
  registry and generated contracts still publish them.
- A URL's `v1`/`v2` segment identifies a contract version, not an implementation
  language. Do not infer runtime from the path.
- Do not redirect a retained v1 operation to v2 merely to reach a different
  implementation. A URL change is a separate API decision.

Auth publishes the same handlers under `/api/v2/auth/*`, `/api/v1/auth/*`, and
`/api/auth/*`; product clients use v2. Other compatibility paths remain only for
existing callers documented in the same-path contract.

### Retired or absent surfaces

- `POST /api/v1/roll/` and `POST /api/roll/` are retired. Roll mutations use the
  v2 resources above.
- `POST /api/v1/rate/` and `POST /api/rate/` are retired. Direct issue read/rate
  uses `PATCH /api/v2/issues/{issue_id}`.
- `GET /api/v1/sessions/`, `GET /api/v1/sessions/{id}`, and their unversioned
  aliases are retired. Use the v2 reading-session details/snapshots resources.
- `GET /api/v2/reading-boundaries/{thread_id}` is retired. The canonical boundary
  operation is the bounded `POST /api/v2/reading-boundaries` batch.
- `GET /api/v1/analytics/metrics` and `GET /api/v2/analytics/metrics` are not
  registered in the service router. The frontend `/analytics` route redirects to
  `/`.
- Admin JSON/CSV import/export endpoints are absent. Database backup and restore
  are operator procedures in [DATABASE_SAVE_LOAD.md](DATABASE_SAVE_LOAD.md).
- The former `/docs`, `/redoc`, `/openapi.json`, and bare `/health` URLs return
  404 from Vercel's explicit legacy-path rule before the SPA fallback.

## Authentication and CSRF

Login returns an access token and sets the refresh cookie. The browser sends the
access token as `Authorization: Bearer ...`. Before an authenticated POST, PUT,
PATCH, or DELETE, fetch `GET /api/v2/auth/csrf` and send the returned token in both
the `csrf_token` cookie and `X-CSRF-Token` header. The refresh cookie alone is not
sufficient for a state-changing request.

Ownership failures return `404` without confirming another reader's resource.
Missing or invalid credentials return `401`; missing or mismatched CSRF returns
`403`.

## Reading List and Roll behavior

Reading Lists are the canonical reader-owned sequence. Natural issue position,
strict/loose list mode, list-local gates, and explicitly reader-authored
prerequisites determine availability. Historical/converted dependency rows are
audit evidence, not execution authority. See
[READING_LIST_RUNTIME.md](READING_LIST_RUNTIME.md) for modes, overlap decisions,
exclusions, and the recorded setting-off discrepancy.

The product target is sessionless Roll with browser-owned pending state
([#4405](https://github.com/JoshCLWren/comic-pile/issues/4405)). Current native
compatibility behavior still initializes six-hour server sessions and stores
pending selection in PostgreSQL. `POST /api/v2/readingSessions` performs that
initialization; `GET /api/v2/roll/bootstrap` is read-only and returns
`404 No active session` until it exists. This server-session boundary is a
recorded discrepancy, not the intended final contract. The Roll pool takes the
top-`die` eligible window first, then removes this browser's temporary snoozes,
with no backfill from deeper ranks.

Direct manual Read/Rate uses `PATCH /api/v2/issues/{issue_id}` with
`source: "direct"` (or omitted). It is allowed for any exact owned issue and does
not step the die or apply Roll queue advancement. A direct unread can reactivate
a completed Thread and assign a queue position. Only a completion with
`source: "roll_offer"` applies Roll rating effects.

## Errors and ownership

- Validation failures use the generated operation's documented status and JSON
  `detail` body; there is no universal Pydantic-style 422 array.
- Core Reading List writes currently return `409` with a plain cycle detail (see
  the reconciliation gaps below).
- Missing and foreign-owned resources return `404`.
- Authentication failures return `401`; CSRF failures return `403`.
- Never log or return credentials, SQL, reset tokens, provider secrets, or raw
  upstream error payloads.

## Configuration

The Vercel entrypoint reads `RUST_ROLL_DATABASE_URL` or `DATABASE_URL`,
`RUST_ROLL_JWT_SECRET` or `SECRET_KEY`, and defaults `RUST_ROLL_ENV` to
`production`. The standalone binary uses `Config::from_env` and requires
`RUST_ROLL_DATABASE_URL` and `RUST_ROLL_JWT_SECRET`; it does not normalize
SQLAlchemy URL prefixes. Both paths share the bounded pool/timeout settings.

`CORS_ORIGINS` and `SESSION_GAP_HOURS` are not read by the current native
configuration. The reading-session gap is fixed by `SessionPolicy::default()`.
The dice ladder is `[2, 4, 6, 8, 10, 12, 20]`, with d6 as the default; native Roll
rating steps use the 4.0 threshold. See
`native/roll-service/src/config.rs` and
`native/roll-service/src/option_e_setting.rs` for the exact settings.

## Regeneration and validation

```sh
cargo run --locked -p comicpile-roll-service --example v2_openapi \
  > native/contracts/v2-runtime.openapi.json
cargo run --locked -p comicpile-roll-service --example same_path_openapi \
  > native/contracts/same-path-runtime.openapi.json
node scripts/export_openapi_schema.mjs
node scripts/generate_openapi_types.mjs
node scripts/generate_openapi_types.mjs --check
```

Rust drift tests and frontend CI verify the checked-in generated artifacts. Do
not edit generated JSON or TypeScript directly.

## Recorded reconciliation gaps

These are known discrepancies, not supported API guidance:

- Core Reading List POST/PUT cycle failures return HTTP `409` with a plain
  `detail`, while the frontend builder still expects a structured HTTP `422`
  `reading_list_cycle` payload. This requires a focused runtime/frontend contract
  repair; documentation must not legitimize either side silently.
- Roll offer and bootstrap always load the canonical eligibility snapshot even
  when the rollout setting is off. The setting changes some projections but does
  not restore the documented stored-`is_blocked` Roll fallback. This contradicts
  the intended setting-off behavior and remains a runtime handoff.
- The retired v1 session list/get callers were removed under #4343. #5708 adds
  the event-derived canonical collection (`GET /api/v2/readingSessions`,
  `GET /api/v2/readingSessions/{session_id}`) without server session lifetime or
  pending state, and moves the existing create/details/snapshot reads onto the
  same lowerCamelCase resource. `frontend/src/services/api-sessions.ts` owns those
  reads; History still uses `/api/v2/activity` for its event stream. Retired v1
  paths are not reintroduced as current guidance.
- Earlier documentation referred to a separate `api/native_issue.rs` ingress. <!-- docs-path-check: ignore -->
  Current `main` builds only `api/native_roll.rs`; bot-owned route outputs are
  regenerated from the route fragments. Do not hand-edit generated route outputs.
