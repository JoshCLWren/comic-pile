# Queue interaction policy

Queue actions must use visible, conventional controls that work with touch, mouse, keyboard, and assistive technology.

Custom horizontal swipe recognition, gesture thresholds, translated card states, delayed click arbitration, and hidden gesture-only actions are prohibited. Browser scrolling and navigation gestures must remain untouched.

Every Queue card action must be reachable through a labeled button or menu control on maintained mobile and desktop layouts. Card activation, keyboard activation, existing drag-and-drop repositioning, dependencies, and ordinary scrolling remain supported.

Tests should exercise the same visible controls a reader uses. Do not simulate removed swipe state or dispatch hidden gesture actions as a shortcut for product behavior.
