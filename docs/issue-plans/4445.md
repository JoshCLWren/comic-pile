# Issue #4445 Plan: App-wide parity - expose direct read/rate on every actionable issue view

## Issue Summary
Implement app-wide parity for direct read/rate actions on every actionable issue view and verify Rust execution in production. This is the behavioral implementation phase after the native API verification slice (PR #4659).

## Owner Objective
Every UI location that renders an identifiable comic issue must provide:
1. The same issue-specific cover rendered directly from ComicVine's CDN
2. Access to the same shared Read now / Rate / Mark read / rating correction workflow
3. Rust execution verified in actual production browser flows

## Current State
- PR #4659 merged: Added native `/api/v2/issues/{id}` read/rate verification spec and updated e2e behavior inventory
- Rust endpoint `PATCH /api/v2/issues/{issue_id}` is implemented (from #4443)
- Shared action/rating component integrated (from #4444)
- Behavioral app-wide parity and authenticated production proof remain

## Technical Requirements

### CDN Image Rendering
- No processing on ComicPile: no image resizing/thumbnail generation, compression, cropping, re-encoding, format conversion, image proxy, binary cache, CDN transformation endpoints, query-parameter rewrites, server fetch or build-time processing
- "Thumbnail" means small CSS presentation of provider art using official small CDN URL when explicitly available
- Batch URL strings and issue metadata, not image bytes
- For unmapped or failed covers, display static text/CSS placeholder
- Production browser/network acceptance assertion: issue cover request hostname is actual URL delivered by ComicVine metadata

### App-wide Reuse Inventory
- Use existing `ComicVineSearchDialog` confirm/replace and `QueueMapSeriesDialog` / `SiblingSeriesMappingOffer` for respective workflows
- No duplicate mapping implementations and no auto-overwriting Annuals/specials
- Correct owner isolation, no N+1 status requests, no image processing
- Bounded data: list APIs include compact per-issue cover/rating projection OR make one batch request for visible owned IDs

### Rust Production Verification
- Verify authenticated Rust execution in actual production browser flows
- Verify route/contract, retry idempotency, and that no Python handler or unused parallel endpoint performs this new command
- Document and retire replaced legacy direct-read client paths only after they are truly unused and production-proven
- Performance check: avoid N+1 rating/status calls and unnecessary Roll bootstrap fetches

## Acceptance Criteria

### Production Acceptance Matrix
| Flow | Required proof |
| --- | --- |
| Strict Mignolaverse CBL Hellboy in Hell ahead of B.P.R.D. | Blocked exact issue has its actual cover and active Read now; rate/mark direct; earlier B.P.R.D. unread and gating unchanged |
| Same comic in Plan, List, Thread, Queue and creator evidence | Same art, exact issue, status, rating and working direct controls after save and page reload |
| Later #10 read ahead of #2 | Only #10 recorded read; #2 still earliest unread and Roll respects eligibility |
| Held/inactive/excluded/already-read comic | Explicit direct action remains available; advisory only; rating edit not duplicate read and no implicit reactivation/reorder |
| Related ComicVine story arc with missing issue | Owned match has direct actions; missing catalog comic has correct art and explicit Add, no unauthorized write |
| Active pending Roll vs manual read | Manual commit does not steal Roll pending selection, touch die/queue or automatically reroll; actual offered-comic completion still performs Roll effects |
| 400+ issue CBL / many Thread rows | Bounded metadata requests; lazy covers; no heavy provider fan-out; image failures preserve controls; mobile scrolling remains usable |
| Production deployment | Authenticated browser tests confirm actual Rust handler, exact issue ID, transactional read/rating, owner isolation and idempotent retry; no Python fallback |
