# Issue #1782: Measure cache lookup latency – Upstash REST vs Neon point SELECT

## Goal

Replace provider-selection folklore with measured numbers. The script must be
self-contained (runs outside the application, depends only on stdlib + `asyncpg`
+ `httpx` for its three measurements) and its results must land in `docs/`
before this issue closes.

## What each measurement represents

| Measurement | What it actually measures | Why it matters |
|---|---|---|
| Upstash REST GET | Round-trip wall-clock for a single cache GET through `upstash-redis` REST; same connection pool and token the application uses | Current remote-cache read latency in Vercel's edge region |
| Neon point SELECT | Round-trip wall-clock for an indexed point SELECT on a small KV-style table in Neon, measured with the same `asyncpg` pool the application uses | Hypothetical Postgres-backed cache lookup at ~same Neon hop count |
| Uncached queue read | Authenticated `GET /api/v1/queue/threads` end-to-end from Vercel region, no `X-App-Cache` header expected | Baseline DB + app response when nothing is cached |

## Files

### New: `scripts/benchmark_cache_latency.py`

Standalone asyncio benchmark. Invocation from Vercel region (e.g. a serverless
function invocation triggered by `curl` or a one-shot `vercel run`):

```
DATABASE_URL=postgresql://... UPSTASH_REDIS_REST_URL=... UPSTASH_REDIS_REST_TOKEN=... \
  python scripts/benchmark_cache_latency.py \
    --upstash-url "$UPSTASH_REDIS_REST_URL" \
    --upstash-token "$UPSTASH_REDIS_REST_TOKEN" \
    --database-url "$DATABASE_URL" \
    --queue-base-url "https://comic-pile.vercel.app" \
    --queue-bearer-token "$BEARER_TOKEN" \
    --iterations 30 \
    --output docs/CACHE_LOOKUP_LATENCY_2026-08.json
```

Flags:

- `--upstash-url` / `--upstash-token` – required; script makes a raw HTTP GET via
  `urllib.request` to the Upstash REST endpoint (mirrors `upstash_redis.asyncio.Redis.get`).
- `--database-url` – required for Neon point SELECT; `asyncpg` pool re-used across
  samples.
- `--queue-base-url` / `--queue-bearer-token` – for the uncached queue read.
- `--kv-table` – optional existing table name for the Neon KV benchmark; default
  `bench_cache_kv`; create if missing (idempotent `CREATE TABLE IF NOT EXISTS`).
- `--iterations` – samples per measurement; default 30.
- `--warmups` – unrecorded warm-up samples to avoid cold-connection bias; default 3.
- `--output` – write JSON report to this path; stdout always printed.

Upstash quota-stopped scenario (current situation, quota resets ~Aug 28):

- The Upstash GET path catches quota/rate-limit HTTP 429 and records the error
  explicitly in the JSON output.
- The other two measurements are unaffected.
