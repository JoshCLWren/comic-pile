# Issue 4337: Legacy rating retirement and post-cutover record

## Status

Route retirement and caller migration landed in #4640 on `main`. This record
documents the delivered contract, the undo regression repaired alongside it, and
the production/performance acceptance that still keeps #4337 open.

- Implementation: #4640 (same repaired branch as #4618)
- Canonical writer: #4443 / `PATCH /api/v2/issues/{issue_id}`
- Remaining acceptance: authenticated production rating, correction and undo;
  issued-SQL/per-request measurement (#4337 and #4443)
- Undo endpoint: retained; it is not part of the rate-router removal

## Owner objective

Retire `POST /api/v1/rate/` and every unversioned rating alias, move Roll and
direct issue rating to the single Rust resource
`PATCH /api/v2/issues/{issue_id}`, preserve the 3.5 direct-read default and the
4.0 Roll threshold, and keep rating corrections and undo working for real
readers.

## Delivered inventory

- `app/api/rate.py`
- `app/services/rate_service.py`
- `app/repositories/rate_repository.py`

`POST /api/v1/rate/` is no longer mounted. In production it answers `404`; the

### Canonical Rust writer

- Ingress: `api/native_issue.rs`
- Handler: `native/roll-service/src/issue_handler.rs`
- Owner-scoped transaction: `native/roll-service/src/issue_service.rs`
- Vercel route: `vercel.json` maps numeric `/api/v2/issues/{id}` `PATCH`
  requests to `api/native_issue.rs`
- Generated contracts: `native/contracts/issue-v2.openapi.json`,
  `native/contracts/v2-runtime.openapi.json`
- Generated frontend schema/client: `frontend/src/generated/openapi.json`,
  `frontend/src/generated/openapi.ts`,
  `frontend/src/generated/nativeV2Client.ts`

The writer owns read/unread, rating correction, idempotent replay, die stepping,
queue placement, pending-offer retirement and linked rate history. It requires
real issue ownership but never re-tests Option E eligibility to reject a comic
the reader already selected (#4453).

### Frontend callers

- `frontend/src/services/nativeRollMutationApi.ts` is the one rating transport.
  It sends `PATCH /api/v2/issues/{issue_id}` with `status`, `rating`, `source`
  and a client-generated retry key.
- `frontend/src/services/protectedRollMutationApi.ts` delegates its `rate`
  method to that transport instead of keeping a second v1 implementation.
- `frontend/src/pages/thread-detail/IssueRateButton.tsx` rates the exact owned
  issue with `source: 'direct'`.
- `frontend/src/pages/RollPage/useRollRating.ts` rates the offered issue with
  `source: 'roll_offer'`.
- `frontend/src/services/api-rate.ts` and its v1-only tests are removed.

## Exact issue resolution

Both rating callers must PATCH a concrete owned `issue_id`; neither path may use
Roll eligibility as an authorization gate.

1. **Session-pending Roll selection:** use the session pending `issue_id`
   carried by the Roll bootstrap/rating state. `handleSubmitRating` reads
   `activeRatingThread.issue_id ?? activeRatingThread.next_issue_id` and refuses
   the request when neither is known.
2. **Manually selected or migrated series:** `handleMigrationComplete` carries
   the offered issue identity forward; `handleSimpleMigrationComplete` resolves
   the exact owned issue from `activeRatingThread.issue_id ??
   activeRatingThread.next_issue_id` before the PATCH and shows an explicit
   error when the identity cannot be resolved.
3. **Direct Thread-row rating:** `IssueRateButton` sends the row's own
   `issue.id`, so a direct read never depends on a pending Roll or on the
   automatic frontier.

## Undo remains part of the contract

Undo is intentionally *outside* the removed rate router:

- Backend: `app/api/undo.py`, mounted at `/api/undo` and `/api/v1/undo` in
  `app/router_mounts.py`
- Frontend: `frontend/src/services/api-undo.ts` and
  `frontend/src/hooks/useUndo.ts`
- Roll UI: `frontend/src/pages/RollPage/index.tsx` sends the latest snapshot to
  `POST /v1/undo/{session_id}/undo/{snapshot_id}`

The retired Python rate writer also created the per-rating undo delta. The
native writer now writes the same version-two compact delta in the same
transaction as the rating (`insert_rating_snapshot` in
`native/roll-service/src/issue_service.rs`):

- the rated thread's pre-action progress, rating, status, manual-placement flag
  and frontier;
- the rated issue's pre-action read state and catalog link;
- only the queue positions and derived blocked flags that changed;
- the active session's pre-action pending offer, snoozes, die and ephemeral
  mode state.

A direct rating without an active reading session still has no session-keyed
undo row, matching the retired writer. The regression test
`test_native_rating_writes_undo_delta_that_python_undo_restores` in
`native/roll-service/parity/test_http_issue_read_rate.py` rates through the real
native PATCH and then applies the retained Python undo service, proving the
issue, thread progress, queue and pending offer return to their pre-rating
state. Rust tests also assert the delta payload, the replay does not write a
second undo point, queue preimages and blocked preimages.

declared complete. Generic exact-head CI or a health check does not establish
them.

- [x] Legacy v1/unversioned rating routes, router mount, service, repository,
  schemas and frontend alias removed.
- [x] Roll and direct rating callers use the single native
  `PATCH /api/v2/issues/{issue_id}`.
- [x] Rust-generated issue contract and generated TypeScript client are checked
  in and drift-tested (`checked_in_openapi_contract_is_current`,
  `tests/test_native_v2_contract_artifacts.py`,
  `tests/test_api_v2_contract_inventory.py`).
- [x] Owner isolation and authentication coverage at the native writer and

  `api/native_issue.rs` routing tests, `tests/test_vercel_deployment.py`).
- [x] Idempotent replay and key-conflict coverage, including no second event or
  undo point on replay.
- [x] Pending offer clearance applies only to the exact rated issue (Q17).
- [x] Undo delta is written by the native writer and consumed by the retained
  Python undo endpoint (native-to-Python parity regression).
- [ ] Authenticated production verification of a real rating, rating correction
  and undo against `https://comic-pile.vercel.app`, with the native runtime
  response and persisted effects observed.
- [ ] Issued-SQL statement count per DB-backed rating/correction request and
  real Fluid/DB usage measured and recorded. This is shared with #4443 and must
  include the undo-snapshot statements added here.
- [ ] Exact-head required CI and independent semantic/acceptance review for the
  deployed revision.

## Rollback

The deployment rollback is the previous Vercel revision. At the database layer,
the native writer and the retained undo service only add ordinary rating events
and delta snapshots; reverting the deployment leaves those rows readable by the
existing undo contract.

## Non-goals

This record does not remove the Python API globally, does not change
`PATCH /api/v2/issues/{issue_id}` into a different API version, and does not
claim that the parent Rust migration (#4335) or the performance acceptance
(#4443) is complete.
