# Issue Plan: Extract session restore and snapshot apply from session.py into services

## Issue Overview
- **Issue**: #2607
- **Part of**: #2594
- **Goal**: Extract session restore and snapshot apply functionality from `app/api/session.py` into proper services and repositories
- **Problem**: Session restore owns retry loops, `select`/`update`/`delete`, snapshot replay, and response assembly in the HTTP layer, plus per-thread N+1 loads

## Files to Examine
- `app/api/session.py` (1260 lines) - contains `restore_session_start` function that needs extraction
- Existing services structure in `app/services/`
- Existing repositories structure in `app/repositories/`

## Implementation Plan

### 1. Create Service Layer
**File**: `app/services/session_service.py`
- `SessionService` class to handle session business logic
- `restore_session_start()` method to move the restore logic from API layer
- Handle retry logic and deadlock handling
- Coordinate with repositories for data operations

### 2. Create Repository Layer
**File**: `app/repositories/session_repository.py`
- `SessionRepository` class for session data operations
- Methods for session queries, snapshot operations
- `SessionSnapshotRepository` for snapshot-specific operations

**File**: `app/repositories/thread_repository.py` (enhance existing)
- Add batch loading methods to eliminate N+1 queries
- Methods for thread restoration from snapshots

### 3. Extract Core Restore Logic
**Current `restore_session_start` function (lines 984-1260)** contains:
- Retry loop with deadlock handling
- Snapshot retrieval and validation
- Thread state restoration (delete, update, create)
- Issue state restoration
- Session state restoration
- Cache invalidation and user status refresh

**Extract into**:
- `SessionService.restore_session_start()` - business logic coordination
- `SessionSnapshotRepository.get_session_start_snapshot()` - snapshot retrieval
- `ThreadRepository.restore_thread_states()` - thread state operations
- `SessionRepository.restore_session_state()` - session state operations

### 4. Fix N+1 Loading Issues
**Current problem**: Per-thread `db.get` loops in restore function
**Solution**: Implement batch loading:
- `ThreadRepository.get_threads_by_ids()` - batch thread retrieval
- `ThreadRepository.get_thread_issue_metadata_batch()` - batch issue metadata
- `ThreadRepository.restore_threads_batch()` - batch thread restoration

### 5. Update API Layer
**File**: `app/api/session.py`
- Remove `restore_session_start` function (lines 984-1260)
- Add dependency injection for `SessionService`
- Router becomes thin - only HTTP handling, validation, and response formatting

### 6. Update Dependencies
**File**: `app/api/session.py`
- Remove direct database operations
- Import `SessionService` and use it for business logic
- Keep HTTP-specific logic (rate limiting, auth, etc.)
