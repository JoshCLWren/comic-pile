# Issue #3226 — DB scale 10: capture compact per-action undo deltas instead of repeating full issue collections

Plan version: 1. Frozen contract per issue body. Depends on #3218 (snapshot kind classification), #3217 (census).

## Problem

`snapshot_thread_states` (rate_service.py:169) currently writes a v2 delta that stores the **entire** pre-state of the rated thread, including its complete `issue_states` collection. For a 10,000-issue thread, every rating serializes all 10,000 issues — unchanged ones included — and undo re-fetches them all. The acceptance contract requires the delta to be bounded by the records actually changed by the action.

## Scope and fixed contract

1. **Compact per-action delta capture.** A v2 rating delta stores only:
   - changed thread fields (the fields that actually moved on this action);
   - changed session fields;
   - queue/blocking changes (already present);
   - created/deleted record **preimages** needed to undo this action (the issue that was read, the issue that became next-unread, the issues created during implicit migration, the threads whose queue position moved — already present).
2. **No unchanged issue collection.** The rated thread's `issue_states` list is replaced by an explicit `issue_changes` list containing only the issues whose state changed on this action (read status, read_at, position) plus preimages of created/deleted issues. Unchanged issues are omitted entirely.
3. **Bounded reads.** Undo restores by applying only the recorded changes; it never re-fetches the full issue collection. Batch read/migration/completion paths legitimately scale with records actually changed.
4. **Backward compatible.** Historical v2 deltas and full-library snapshots keep decoding/restoring exactly as before. The new compact payload is additive: existing readers of the payload (`_apply_delta_snapshot`, `_restore_issue_states`) learn to handle an optional `issue_changes` key while still honoring `issue_states` when present.
5. **Atomic capture.** Preimages are captured before mutation; the action, event, and delta are written atomically in one transaction.
6. **Preserve Session start snapshots and RESTORE START semantics.** `create_session_start_snapshot` is unchanged; it keeps its full-library contract. Retention and history are untouched.

## Implementation steps

1. **Snapshot contract (`app/services/snapshot_contract.py`)**: add `ISSUE_CHANGES_KEY = "issue_changes"` and `THREAD_CHANGES_KEY = "thread_changes"` constants plus a `compact_delta` flag helper.
2. **Rate service (`app/services/rate_service.py`)**:
   - Refactor `_capture_thread_pre_state` into `_capture_thread_full_state` (full, used by legacy/session-start writers) and `_capture_thread_changed_state` (compact, used by the v2 rating delta).
   - In `rate_thread`, compute the set of issue IDs whose state changed on this action (the read issue, the new next-unread issue, migration-created issues) and capture only their preimages. Record the rated thread's changed thread fields and the created/deleted issue preimages.
   - Pass the compact pre-state into `snapshot_thread_states`.
3. **Undo service (`app/services/undo_snapshot_service.py`)**: `_apply_delta_snapshot` / `_restore_issue_states` learn to apply `issue_changes` (update-or-create the listed issues, delete listed preimage-deleted issues) while keeping the legacy `issue_states` path intact.
4. **Repository (`app/repositories/undo_snapshot_repository.py`)**: add helpers `get_issues_by_ids` (already present as `get_issues_by_thread_ids` — reuse) and `delete_issues_by_ids` (already present). No new persistence primitives required.
5. **Tests**: extend `tests/test_delta_undo_regressions.py` with a 10k-issue payload-size/row-count assertion; add `tests/test_delta_compact_capture.py` covering compact capture, undo parity, migration preimages, and die/pending-state restoration.

## Risks / frozen boundaries

- Async PostgreSQL only in application code.
- No schema change; payloads stay JSON.
- Preserve existing IDs, wire contracts, history, personal notes, ratings, queue intent, plan/provenance links.
- Do not resurrect `Thread.format` (#3035) or duplicate manual creator-entry UX (#3145).
- Session-start snapshots remain full-library; RESTORE START unchanged.
