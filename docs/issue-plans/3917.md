# Contributor execution trust boundary

Contributor PRs retain the normal review → repair → exact-head CI → merge lifecycle.
Their source must never execute in a credentialed factory worker.

## Frozen execution contract

1. The ordinary controller assigns fork reviews to OpenCode workers. The worker stays
   on trusted main, builds an exact-head source/issue/review snapshot as data, and
   invokes its pinned model from an isolated configuration with all tools and
   integrations hard-denied. It receives only the selected provider credentials;
   repository write credentials are not passed to the model process. The existing
   trusted exact-head review controller interprets the real verdict.
2. Fork repairs use existing anonymous Kilo workers. The credentialed parent only
   writes a trusted dispatch receipt and starts the main-branch `Factory Fork
   Execution` workflow, retaining its lease. That workflow has read-only permissions,
   no inherited repository/provider secrets, and runs dependency installation,
   contributor code, tests, and normal commit hooks on its separate ephemeral runner.
   Repair artifacts never authorize semantic approval.
3. `Factory Fork Persistence` runs trusted main code after execution completes. It
   validates the actual workflow ID/path/event/ref/repository, a controller-bot receipt,
   current lease, PR destination and head, bounded artifact structure, and a single
   descendant commit. It imports Git objects into a bare quarantine without checking
   out artifact source. Only this trusted process receives the fork push credential.
   It records contributor provenance and returns the new head to independent review.
4. Active execution runs keep the corresponding worker lease live. Failed executions
   release truthful repair state and enter the bounded generation-scoped retry gate.
   A stale result cannot overwrite a changed head or another worker's lease.

No branch-supplied script, dependency, hook, plugin, or test is executed by the
credentialed parent or persistence process. Metadata and artifacts are data. Read-only
fork CI includes the same system tools as the ordinary CI image, including `jq`.

## Verification

- Poisoned fork scripts cannot run through the credentialed checkout path.
- Static-review configuration denies every tool and integration, from a trusted
  working directory, and excludes GitHub/write credentials from the child environment.
- The execution workflow contains no repository-secret references or inherited secrets.
- Forged workflow identity/receipts, stale leases/heads, changed destinations, oversized
  or unexpected artifacts, and invalid commit ancestry are rejected before any push.
- A real fork repair produces a descendant commit, runs read-only CI, receives an
  independent exact-head review, and preserves the original contributor's history.

OpenCode's policy semantics are documented at
https://dev.opencode.ai/v2/docs/policies: `tool.use` denies apply after tool permissions;
`integration.use` can prevent MCP servers, skills, and plugins from loading.
