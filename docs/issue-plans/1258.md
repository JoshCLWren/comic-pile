# Issue #1258 Plan: Make continuity graph loading bounded and reusable per request

## Scope
- Measure and document current query count/rows for `_load_snapshot`
- Consolidate snapshot queries where practical (target: fewer than 6 queries)
- Make `_load_snapshot` reusable within one database session/request so multiple continuity calculations on the same user load once
- Preserve bounded limits, deterministic cycle handling, branch/convergence semantics
- Add regression coverage for query-count growth with larger user graphs

## Key files
- `app/continuity_readiness.py` (snapshot loader, readiness evaluator)
- `app/continuity_chains.py` (traversal that also loads snapshot)
- `app/continuity_blocking.py` (blocked-state loader)
- `app/roll_recovery.py` (calls `resolve_continuity_chains` -> loads snapshot)
- `app/roll_recovery_switch.py` (calls `resolve_continuity_chains` + `build_roll_recovery` repeatedly)
- `tests/test_continuity_readiness_chains.py`
- `tests/test_continuity_blocked_state.py`

## Risks
- Changing query structure must preserve bounded limits (`limit()` on parent entities)
- `joinedload` duplicates parent rows; must deduplicate properly in Python
- Reusing snapshot via `db.info` must not leak across different users in same session
- Must not break async PostgreSQL rules

## Implementation steps
1. Consolidate snapshot queries using `joinedload` or similar where safe
2. Cache snapshot in `db.info` keyed by `(user_id, snapshot_version)`
3. Add `QueryCountTracker` or similar measurement wrapper
4. Document before/after query counts
5. Add regression test that verifies no duplicate snapshot loads per session
6. Add regression test for query growth limits
