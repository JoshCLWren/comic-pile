# Issue #4204: Thread row Rate (#4194) - Fix Plan

## Problem Summary

Two acceptance criteria gaps from PR #4194:

1. **Saved rating not shown in context after reload**: After rating from a Thread row, the row shows "Rated 4" immediately, but after page reload it shows a bare "Rate" button.

2. **No Undo record**: Rating from a Thread row should produce the same Undo/History entry that Roll ratings produce.

## Root Causes

### Gap 1: Saved Rating Persistence

- `IssueRateButton` uses local React state `savedRating` which is lost on page reload
- The API doesn't return per-issue rating information
- The thread's `last_rating` is the most recent rating, not the specific issue's rating

### Gap 2: Missing Snapshots for Direct Ratings

In `app/services/rate_service.py`:
- Snapshots are only created when `current_session is not None` (line 876)
- Direct Thread ratings (`is_direct = True`) don't require an active session
- Without a session, no snapshot is created, so no undo record exists

## Implementation Plan

### Part 1: Persist Rated Issue Durable Storage (Frontend)

**File**: `frontend/src/pages/thread-detail/IssueRateButton.tsx`

1. Add `localStorage` persistence for rated issues: store `rated_issues: { [issue_id: string]: rating }` with key `thread-rated-issues-{thread_id}`
2. After successful rating, write to localStorage and update the thread cache
3. On component mount, read from localStorage and populate the cache with rated issues
4. Use `applyRatedThreadCache` helper to update the cache with the persisted data
5. On Undo of a rating, remove the corresponding issue_id entry from localStorage and update the thread cache to clear the "Rated X" state, ensuring reopening the thread does not restore the undone rating

### Part 2: Create Snapshots for Direct Thread Ratings (Backend)

**File**: `app/services/rate_service.py`

1. Modify `snapshot_thread_states` call to always create a snapshot for direct ratings
2. When `current_session is None` for direct ratings, create a temporary session state using `session_state_from_thread(thread_id, user_id)` which fabricates a minimal session with the thread as the current reading state
3. Store the snapshot with the event ID so it can be retrieved for undo
4. The snapshot will be keyed by the fabricated session_id, allowing it to appear in History/Undo under that session

### Part 3: Add Undo Endpoint for Direct Ratings (Backend)

**File**: `app/api/undo.py`

1. Modify `undo_to_snapshot` to accept direct Thread ratings (session_id is still required for the snapshot, but we can create one for the thread)
2. Actually, better approach: Create a snapshot even when no session exists, keyed by the thread_id

Wait, looking at the snapshot contract more carefully, snapshots are keyed by `session_id`. So we need a different approach.

**Better approach**: Create a snapshot for direct ratings even without a session by creating a temporary session or using the thread_id as the key.

Actually, reviewing the code more carefully, I see that snapshots ARE being created for direct ratings on line 880-894, but only when `current_session is not None`. The comment says "Undo snapshots are keyed by reading session; a direct Thread rate submitted without a session has no session to key an undo record to."

So the fix is simple: **Create the snapshot even when `current_session is None` for direct ratings**.

## Changes Required

### Frontend

1. **IssueRateButton.tsx**: Persist rated issues in localStorage and cache
   - Write rated issues to `localStorage.setItem('thread-rated-issues-{thread_id}', JSON.stringify(rated_issues))`
   - Read from localStorage on mount and merge into the thread cache
   - Use `applyRatedThreadCache` to update the cache with persisted rated issue data
   - On Undo, remove the undone issue's entry from localStorage and invalidate the thread cache entry so the row reverts to a plain "Rate" button

### Backend

1. **rate_service.py**: Create snapshots for direct Thread ratings
   - Move the `snapshot_thread_states` call outside the `if current_session is not None` block
   - When no session exists, create a minimal session state using `session_state_from_thread(thread_id, user_id)` which fabricates a session with the thread as the current reading state
   - This provides a valid session_id for snapshot creation while keeping the snapshot linked to the thread
