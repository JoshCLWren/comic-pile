# Issue #3375 — Plan: GET /api/v1/roll/bootstrap 1962ms > 1000ms budget

## Contract

Production cold request `GET /api/v1/roll/bootstrap` took 1962.04ms against a
1000ms budget, with 36 DB queries and 1326.82ms of DB time. Signature
`request|GET|/api/v1/roll/bootstrap|cold|unknown|db-heavy`. Factory note:
investigate with request diagnostics and Server-Timing instrumentation; do
not raise global thresholds.

## Root-cause hypothesis

Confirmed. `roll_bootstrap` (app/api/roll.py) built the response with up to
eleven sequential `await db.execute(...)` round trips inside one request. The
route was a legacy layering violation (`roll: ["execute-call",
"query-import"]` in `tests/router_layering_baseline.json`), and the v2 sibling
`roll_v2_bootstrap` already had a bounded projection
(`app/services/roll_v2_projection.py` +
`app/repositories/roll_v2_projection.py`). The v1 endpoint was left behind.

The dominant cost was **per-summary round trips, not per-row work**. The roll
pool, snoozed, skipped, blocked-count, blocked-detail, stale-count, stale-ids,
stale-detail, all-active, and completed summaries each re-read overlapping
columns of the same owned threads. Collapsing them into one owned-thread
inventory read plus one bounded pool read is the fix. No global threshold
change.

## Files

- `app/repositories/roll_bootstrap_repository.py` — new: `fetch_owned_thread_inventory`
  (one read of every owned series) and `fetch_roll_pool_rows` (one bounded pool
  read carrying the next issue number and the correlated route-label aggregate).
- `app/services/roll_bootstrap_service.py` — new: `build_roll_bootstrap_response`
  assembles the v1 `RollBootstrapResponse` from those two fetches plus the
  existing session/die/recovery helpers.
- `app/api/roll.py` — `roll_bootstrap` now validates and delegates to exactly
  one service call; the now-unused query imports are gone.
- `app/schemas/roll.py` — unchanged (response contract is frozen).
- `tests/test_roll_bootstrap_ownership.py`,
  `tests/test_session_timezone_capture.py`,
  `tests/test_taste_acceptance.py` — updated for the new collaborators, plus a
  query-count guard that pins the `threads` read count.

## Implementation steps

1. Create `app/repositories/roll_bootstrap_repository.py` with two bounded
   fetchers. The inventory returns every status because the snoozed/skipped
   summaries address stored session ids without a status filter. The pool fetch
   is skipped entirely for an empty pool and keeps the correlated
   `array_agg(distinct ...)` route-label subquery.
2. Create `app/services/roll_bootstrap_service.py` with
   `build_roll_bootstrap_response`. The predicates that used to run in SQL -
   active status, `queue_position >= 1`, `is_blocked`, snoozed/skipped
   membership, and the seven-day `coalesce(last_activity_at, created_at)`
   cutoff - are pure functions of the inventory columns and are evaluated in
   Python over one ordered fetch. Session mode, active thread, die, and
   recovery resolution are unchanged.
3. Refactor `roll_bootstrap` to call the service exactly once. Keep the
   timezone-capture block inside the service so `db.commit`/`db.refresh` and
   the MissingGreenlet extraction rules are unchanged.
4. Add a regression guard pinning the `threads` read count and update the
   mock-coupled unit tests to patch the service and repository collaborators.

## Risks

- The v1 response contract is frozen and consumed by the frontend
  (`frontend/src/types/rollBootstrap.ts`, `useRollBootstrap.ts`). Do not
  change field names or shapes.
- `RollBootstrapResponse` has a `model_validator` that bounds summary lists;
  preserve it.
- `tests/router_layering_baseline.json` keeps `roll: ["execute-call",
  "query-import"]`: the module's other endpoints (v2 bootstrap, `roll`,
  `session_mode`) still execute queries, so migrating this route alone does not
  change the module's violation set. The conformance ratchet is shrink-only and
  must not be edited to claim a clean module.
- MissingGreenlet rule: extract session attributes before `db.commit()` in the
  timezone block (already done).
- The stale nudge must keep excluding cross-session and current-session snoozed
  series but *not* skipped series, matching the previous SQL predicates.
