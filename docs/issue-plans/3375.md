# Issue #3375 — Plan: GET /api/v1/roll/bootstrap 1962ms > 1000ms budget

## Contract

Production cold request `GET /api/v1/roll/bootstrap` took 1962.04ms against a
1000ms budget, with 36 DB queries and 1326.82ms of DB time. Signature
`request|GET|/api/v1/roll/bootstrap|cold|unknown|db-heavy`. Factory note:
investigate with request diagnostics and Server-Timing instrumentation; do
not raise global thresholds.

## Root-cause hypothesis

`roll_bootstrap` (app/api/roll.py:1035) builds the response with ~13 sequential
`await db.execute(...)` round trips inside one request. The route is already
in `tests/router_layering_baseline.json` as a legacy layering violation
(`roll: ["execute-call", "query-import"]`), and the v2 sibling
`roll_v2_bootstrap` (app/api/roll.py:1434) was already migrated to a
constant 3-round-trip projection (`app/services/roll_v2_projection.py` +
`app/repositories/roll_v2_projection.py`). The v1 endpoint was left behind.

The dominant cost is per-query round trips. Collapsing the sequential
queries into a small constant number of batched queries — mirroring the v2
pattern — is the fix. No global threshold change.

## Files

- `app/api/roll.py` — `roll_bootstrap` (line 1035): replace inline query
  construction with service/repository calls.
- `app/repositories/roll_repository.py` — add `fetch_v1_bootstrap_pool_data`
  (single batched query for pool + snoozed + skipped + blocked + stale +
  snapshot count).
- `app/services/roll_bootstrap_service.py` — new: assemble the v1
  `RollBootstrapResponse` from the batched repository rows plus the existing
  session/recovery helpers.
- `app/schemas/roll.py` — unchanged (response contract is frozen).
- `tests/test_roll_api.py` / `tests/test_roll_bootstrap_ownership.py` /
  `tests/test_roll_bootstrap_exclusions.py` — existing tests must keep
  passing; add a query-count regression guard.

## Implementation steps

1. Create `app/services/roll_bootstrap_service.py` with
   `build_roll_bootstrap_response(db, *, user_id, current_session, ...)`.
   It owns the orchestration: session mode, active thread, recovery, and the
   batched pool fetch.
2. Add `fetch_v1_bootstrap_pool_data` to `app/repositories/roll_repository.py`.
   One `SELECT` for the pool (with the correlated route-labels subquery, the
   existing `array_agg(distinct ...)` pattern), one `SELECT` each for snoozed,
   skipped, blocked count, blocked detail, stale count, stale detail, and the
   snapshot count — all batched where possible. Preserve the exact v1
   predicates (active, queue_position >= 1, not blocked, snoozed/skipped
   exclusions, 7-day stale cutoff, coalesced activity, summary_limit=20).
3. Refactor `roll_bootstrap` to call the service exactly once and map the
   result to `RollBootstrapResponse`. Keep the timezone-capture block and the
   `get_or_create`/`get_session_with_thread_safe`/`get_current_die_for_session`
   calls where they are (they are not the hot path).
4. Shrink `tests/router_layering_baseline.json` entry for `roll` to `[]`
   once the router is clean, and add a regression test asserting the v1
   bootstrap SELECT count does not grow with pool size.

## Risks

- The v1 response contract is frozen and consumed by the frontend
  (`frontend/src/types/rollBootstrap.ts`, `useRollBootstrap.ts`). Do not
  change field names or shapes.
- `RollBootstrapResponse` has a `model_validator` that bounds summary lists;
  preserve it.
- The route is a legacy layering violation; migrating it shrinks the baseline.
  The conformance test enforces shrink-only, so this is allowed.
- MissingGreenlet rule: extract session attributes before `db.commit()` in the
  timezone block (already done).
