# Issue #2606: Extract roll orchestration from roll.py into roll services

## Problem
`app/api/roll.py` is the largest API module (~1650 lines) with ~38 `select`/`execute` sites. Roll selection orchestration, session mutation, and response building live in the router, violating the layered architecture.

## Files
- **Current**: `app/api/roll.py` (1650 lines, ~38 query sites)
- **New**: `app/services/roll_service.py` (core roll orchestration)
- **New**: `app/repositories/roll_repository.py` (DB query operations)
- **Modified**: `app/api/roll.py` (shrunk to validation + one service call per endpoint)
- **Modified**: `tests/router_layering_baseline.json` (reduce `roll` violations)
- **New**: `tests/test_roll_service.py` (service tests)
- **New**: `tests/test_roll_repository.py` (repository tests)

## Current Flow
Endpoints in `app/api/roll.py` directly:
1. Call `get_or_create` / `get_current_die_for_session` (from `comic_pile.session`)
2. Execute `select`/`execute` queries inline
3. Build `Event`, `RecommendationContext` objects
4. Call `db.add`/`db.commit`/`db.flush`
5. Call `_invalidate_session_caches`
6. Build `RollResponse` from model attributes

## Target Architecture

### `app/repositories/roll_repository.py`
Owns all SQLAlchemy query construction for roll operations:
- `get_bounded_roll_pool_rows` — delegate to `comic_pile.queue`
- `fetch_session_events` — query events for a session
- `fetch_thread_by_id` — find a thread with ownership check
- `fetch_issue_by_id` — find an issue
- `fetch_session_for_roll` — get active session with all needed attributes
- `insert_event` — add an Event row
- `insert_recommendation_context` — add a RecommendationContext row
- `update_session_pending_thread` — set pending thread on session
- `clear_session_pending` — clear pending thread
- `fetch_bootstrap_data` — all queries for the bootstrap endpoint
- `fetch_recommendation_explanation` — query for explanation endpoint
- `fetch_session_for_unskip` — session queries for unskip endpoint
- `update_session_skipped` — modify skipped thread list

### `app/services/roll_service.py`
Owns all business logic and transaction boundaries:
- `select_pending_thread` — the shared selection logic (extracted from `_select_pending_thread`)
- `build_roll_response` — convert artifacts to `RollResponse`
- `build_rolling_recommendation_context` — build the rolling context dict
- `execute_roll` — full roll_dice flow: validate, select, commit, invalidate
- `execute_skip` — full skip flow
- `execute_override` — full override flow
- `execute_dismiss_pending` — clear pending roll
- `execute_unskip` — remove thread from skip list
- `execute_roll_bootstrap` — bootstrap data assembly
- `execute_recommendation_explanation` — explanation lookup

### `app/api/roll.py` (shrunk)
Each endpoint becomes:
1. Validation (auth, request params)
2. One service call
3. HTTP status mapping
4. Return response

## Acceptance Criteria
1. Core roll selection + commit path lives in services/repositories
2. Router shrinks to validation + one service call per endpoint
3. `roll` baseline entry in `tests/router_layering_baseline.json` materially reduced
4. Roll API + related tests pass
5. `bash scripts/check-python-ci-lint.sh` passes
