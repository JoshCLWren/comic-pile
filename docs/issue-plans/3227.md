# Issue #3227 — DB scale 11: use sparse internal queue order keys while preserving dense API positions

Plan version: 1. Frozen contract per issue body. Depends on #3217, #3226.

## Problem

Dense queue_position updates amplify writes for long queues. Add nullable BIGINT
internal queue_order_key; preserve dense 1-based queue_position at API boundaries
via reader-scoped projections.

## Scope

- Add `threads.queue_order_key BIGINT NULL` (migration p322700000001).
- Backfill in bounded batches with legacy fallback (queue_position-derived key)
  until complete.
- Reader-scoped ordering uses COALESCE(queue_order_key, queue_position * scale).
- Single moves update only moved records when gap exists; rebalance transactionally
  when no gap remains.
- Undo captures changed internal keys.
- Natural Issue.position unchanged.
