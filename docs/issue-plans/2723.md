# Issue plan: #2723 — Roll: integrate Map series into unresolved idle rows

## Current product truth (post-revert investigation)

- The idle Roll v2 cutover (#2719, PR #4264) was **reverted** in #4316 because
  `GET /api/v2/roll/bootstrap` returns 503 on prod at d100 (open P0 #4315,
  actively owned by another factory worker). Idle Roll serves
  `/api/v1/roll/bootstrap` again and pool rows are `RollBootstrapThread`
  (title/format/issue/routes/tags) — they carry **no identity state**.
- The #4318 frozen Python behavior oracle pins the complete **v2** bootstrap
  HTTP payload (`tests/fixtures/roll-v2/v1/*.json`); the Rust Roll epic
  (#4299..#4314) depends on that stability. Adding fields to either bootstrap
  response, or re-landing the v2 client, is therefore out of scope for this
  issue and would fight (#4315, Rust epic, frozen oracle).
- The **shared Map series dialog already exists and is reused across surfaces**
  (`QueueMapSeriesDialog` — used by the Queue cards and already by the Roll
  rating view through `ComicPillar`). It implements search → preview → commit,
  unavailable-scope handling, stale preview re-reading, cancel safety, and
  provider-failure containment, with focused Vitest coverage for every
  scenario named in the issue's acceptance contract.
- The commit hook (`useQueueSeriesMappingCommit`) already invalidates the roll
  bootstrap (`invalidateAfterQueueMovement` touches
  `queryKeys.roll.bootstrap()`), so a successful commit refreshes Roll state.

## What is genuinely missing

1. **No way for an idle pool row to know it is unresolved/ambiguous.** The v1
   pool rows carry no mapping state, and neither bootstrap may change.
   The truthful gate must be fetched on demand.
2. **No per-thread mapping-health endpoint.** `ComicVineMappingHealth` exists
   as the `ThreadListItem` queue projection only
   (`fetch_comicvine_mapping_health` repo query + `to_queue_list_item`
   status derivation). A small authenticated per-thread endpoint can reuse
   exactly those pieces — one bounded, user-triggered read at action-sheet
   open, never at Roll view load (does not regress #4276/#3375 fan-out or
   bootstrap budgets).
3. **No idle-Roll entry point.** The pool row's action sheet
   (`RollModals`) is where row actions live.

## Design

### Backend (additive, no bootstrap contract change)

- `GET /api/v1/threads/{thread_id}/comicvine-mapping-health`
  (`app/api/thread.py`, auth-required, service call only):
  - service `app/services/thread_service.get_thread_comicvine_mapping_health`:
    ownership-check `_require_owned_thread`, then the existing batched
    `thread_repository.fetch_comicvine_mapping_health`, then the existing
    status derivation;
  - extract that derivation from `to_queue_list_item` into the shared pure
    helper `build_comicvine_mapping_health(mapping_health, total_issues)` so
    Queue rows and the new endpoint cannot drift.
- Regenerate `frontend/src/generated/openapi.{json,ts}` via
  `pnpm generate:api-types`.

### Frontend

- `services/api-threads.ts`: `comicvineMappingHealth(threadId)`.
- `hooks/useRollSeriesMapping.ts`:
  - `useRollMappingHealth(threadId, enabled)` (query key
    `queryKeys.comicVine.mappingHealth(threadId)`), only run while the action
    sheet is open;
  - pure gate `isRollMapSeriesCandidate(health | undefined | null)`:
    `unresolved`, `needs_review`, or `partial` (partial always has unmapped
    issues); `fully_mapped` and `not_applicable` are excluded; a failed fetch
    is never a candidate (backend unavailable → fails closed, Roll stays
    usable).
- `query/queryKeys.ts` comicVine.mappingHealth, `query/cacheEffects.ts`
  `invalidateComicVineMappingHealth`.
- `components/QueueMapSeriesDialog.tsx`: optional `knownIssueNumber`
  prop rendered as quiet issue context in the search step, so the row's known
  issue number is preserved while searching (Queue and ComicPillar callers are
  unaffected).
- `pages/RollPage/`:
  - `useRollPageState`: `isMapSeriesOpen`;
  - `useRollActions.handleAction('map-series')`: open the dialog;
  - page: hold the health query while the sheet is open, pass
    `mapSeriesAvailable` + dialog props into `RollModals`;
  - `RollModals`: show a "Map series" action-sheet item only when
    `mapSeriesAvailable`, render the shared
    `QueueMapSeriesDialog` for `selectedThread`; `onMapped` invalidates the
    row's mapping health so reopening the sheet reflects the new state.
- Cancel/close paths mutate nothing; the dialog already commits only on
  explicit approve.
