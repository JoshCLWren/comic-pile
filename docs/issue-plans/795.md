# Issue #795: P0: Surface and recover from post-snooze bootstrap refresh failures

## Files to modify
- `frontend/src/hooks/useSnooze.ts` - main hook implementation
- `frontend/src/components/SnoozeControls.tsx` - UI to display recovery state and retry action
- `frontend/src/components/QueuePage.tsx` - ensure no duplicate submissions during recovery
- `frontend/src/components/RollPage.tsx` - ensure Roll state updates after recovery

## Current flow analysis

### useSnooze.ts current state:
- Has `refreshError` state that is set when `fetchAndPublishRollBootstrap()` fails
- Has `retryRefresh()` function to retry the bootstrap refresh
- Has `clearRefreshError()` to clear the error state
- The snooze mutation itself is not blocked while refresh recovery is pending

### Problem identified:
1. After snooze succeeds and bootstrap refresh fails, the hook exposes `refreshError` but callers don't know to prevent duplicate snooze submissions
2. The UI doesn't show recovery state or retry action clearly
3. Roll state doesn't automatically update after recovery without manual refresh
4. No bounded retry mechanism - only one retry attempt

## Required changes

### 1. useSnooze.ts modifications:
- Add `refreshRecoveryPending` state to track when refresh recovery is in progress
- Add `refreshRetryCount` state to track retry attempts (bounded to 3)
- Modify `mutate()` to prevent duplicate submissions during refresh recovery
- Modify `retryRefresh()` to implement bounded retry (max 3 attempts)
- Ensure `isPending` reflects refresh recovery state, not just mutation
- Export new states: `refreshRecoveryPending`, `refreshRetryCount`

### 2. SnoozeControls.tsx modifications:
- Display refresh error message when present
- Show retry refresh button when refreshError exists
- Disable snooze button during refresh recovery
- Show loading state for refresh recovery
- Display retry attempt count (e.g., "Retry 1/3")

### 3. QueuePage.tsx modifications:
- Ensure snooze mutation is blocked during refresh recovery
- Pass `refreshRecoveryPending` to snooze controls

### 4. RollPage.tsx modifications:
- Subscribe to roll state updates after recovery
- Ensure Roll component re-renders when bootstrap is published after recovery

## Test requirements

1. successful snooze followed by failed bootstrap refresh → refreshError set, no isError
2. retryRefresh() with bounded attempts (max 3) → stops after 3 failures
3. retryRefresh() succeeding → publishes bootstrap, clears error
4. no duplicate snooze request while refresh recovery pending → blocked by inFlightRequest
5. Roll state updates after successful recovery → verified by component re-render
6. mutation is never falsely presented as uncommitted → snooze result returned correctly
