# Issue #3828: cooldown unavailable live OpenCode free models

The live catalog can contain a free model that cannot actually be invoked. Keep
free-only rotation and bounded exact-model smoke, but exclude a model for six
hours after trusted evidence that its invocation returned `Model unavailable`.

## Implementation

- `factory_live_opencode.py` reuses the shared trusted registry parser and retains
  each record's timestamp. It accepts paginated GitHub comment JSON and ignores
  untrusted authors/apps, malformed records, future timestamps, unrelated provider
  failures, and expired temporary exclusions. Actual retirement remains sticky.
- The dispatch selector fetches registry #1093 comments and supplies them to the
  live selector. Failure to read evidence fails closed. An exhausted free pool
  fails without selecting a paid fallback; Big Pickle remains a normal candidate.
- The bounded smoke step records exact selected-model unavailability in
  `factory-discovery-outcome`. Quota, timeout, generic failure, and another model's
  error do not create this model's cooldown.
- The terminal reporter publishes a separate run-specific failure snapshot with
  source, selected model, run ID, timestamp, detail, and normalized outcome. It
  strips the mutable worker marker so later worker reports cannot overwrite this
  evidence. The existing worker summary continues to update normally.
- No runner-local cooldown file is used: temporary runner storage does not survive
  future dispatches. Registry evidence supplies the durable six-hour expiry.

## Risk and rollback

Changes affect factory selection and telemetry only, without production data or
schema changes. Revert the selector and workflow changes together to restore the
prior behavior. Never change paid-model eligibility or remove the smoke timeout.
