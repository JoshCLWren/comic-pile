# Issue #2126: CBL adoption: build read-only preview and adoption-plan API

## Goal

Build the backend read-only preview/planning layer for one CBL source list. This issue must not create or mutate user-owned reading state.

The output of this issue is a stable API contract that Child B can consume transactionally and Child C can render directly.

## Product contract

CBL controls source order. The reader controls membership.

Selecting or previewing a CBL must be non-destructive. Existing canonical ComicPile issues should be reused when they resolve. Missing or ambiguous entries must be surfaced, not silently created or dropped.

## Required behavior

### Core API endpoints

1. **Preview endpoint** (`GET /api/v1/cbl-lists/{list_id}/preview`)
   - Authenticated endpoint that previews a persisted CBL source list for the current user
   - Returns `CBLPreviewResponse` with:
     - All source positions in CBL order (from `CBLSourceEntry.position`)
     - Resolution status for each entry (existing, missing, ambiguous, duplicate)
     - Existing canonical issue mapping with read status/history preserved
     - Source metadata (list name, repository, path, etc.)

2. **Plan calculation endpoint** (`POST /api/v1/cbl-lists/{list_id}/calculate-plan`)
   - Accepts `CBLPlanCalculationRequest` with decisions (series inclusion, entry overrides, etc.)
   - Returns `CBLPlanCalculationResponse` with:
     - Mutation summary without performing changes
     - Proposed source-backed order with gaps preserved
     - Conflict analysis for duplicate/ambiguous entries

### Data models required

#### `CBLPreviewResponse`
```python
@dataclass(frozen=True, slots=True)
class CBLPreviewResponse:
    """Read-only preview of a CBL source list for a user."""
    
    list_id: int
    list_name: str
    source_path: str
    declared_issue_count: int | None
    source_repository: str | None
    
    # Per-position data preserving exact source order
    positions: tuple[CBLPreviewEntry, ...]
    
    # Summary statistics
    total_positions: int
    resolved_count: int
    unresolved_count: int
    ambiguous_count: int
    duplicate_identity_groups: int
    
    first_unread_position: int | None
    first_unread_entry: CBLPreviewEntry | None

@dataclass(frozen=True, slots=True)
class CBLPreviewEntry:
    """One CBL source position with resolution and read context."""
    
    cbl_position: int
    series_name: str
    issue_number: str
    comicvine_issue_id: str | None
    external_issue_identity_id: int | None
    external_series_identity_id: int | None
    
    # Resolution results from #2126 work
    resolved_issue_id: int | None
    canonical_issue_id: int | None
    resolution_status: str  # "existing", "missing", "ambiguous", "duplicate"
    is_duplicate_identity: bool
    
    # User-specific state preservation
    read_status: str  # "read" or "unread"
    read_at: datetime | None
    rating: float | None
    events: tuple[dict[str, object], ...]
    
    # Source evidence
    cbl_entry_id: int
    volume_year: int | None
    publication_year: int | None
```

#### `CBLPlanCalculationRequest`
```python
class CBLPlanCalculationRequest(BaseModel):
    """Reader decisions for selective CBL adoption."""
    
    # Per-entry inclusion decisions
    entry_decisions: dict[int, str]  # cbl_position -> "include" | "exclude"
    
    # Series-level decisions (override all entry decisions)
    series_decisions: dict[str, str]  # series_name -> "include" | "exclude"
    
    # Individual overrides of series decisions
    series_overrides: dict[str, dict[int, str]]  # series_name -> {cbl_position: decision}
```

#### `CBLPlanCalculationResponse`
```python
@dataclass(frozen=True, slots=True)
class CBLPlanCalculationResponse:
    """Adoption plan without materializing changes."""
    
    # Propose entries that will be included
    proposed_entries: tuple[CBLProposedEntry, ...]
    
    # Actions that would occur on commit
    planned_actions: tuple[CBLPlannedAction, ...]
    
    # Source-backed order summary
    adopted_count: int
    adopted_positions: tuple[int, ...]
    excluded_positions: tuple[int, ...]
    unresolved_positions: tuple[int, ...]
    
    # Validation warnings
    warnings: tuple[str, ...]

@dataclass(frozen=True, slots=True)
class CBLProposedEntry:
    """Entry that will be included in the adopted source order."""
    
    cbl_position: int
    series_name: str
    issue_number: str
    resolved_issue_id: int | None  # None = missing, will need creation
    existing_issue_id: int | None  # Existing issue to reuse (None if new)
```

## Implementation details

### API Contract Location
- **File**: `app/api/cbl_adoption.py`
- **Router**: "cbl-adoption" tag

### Service Layer
- **File**: `app/services/cbl_adoption.py`
- **Functions**:
  - `preview_cbl_source_list(db, user_id, list_id)` -> `CBLPreviewResponse`
  - `calculate_cbl_adoption_plan(db, user_id, list_id, decisions)` -> `CBLPlanCalculationResponse`

### Integration with existing reconciliation
- Reuse `reconcile_cbl_source_list` from `app/services/cbl_reconciliation.py`
- Use `resolve_cbl_entries_to_canonical` from `app/services/issue_identity_reconciliation.py`
- Preserve existing read history, ratings, events, and canonical identities

### Data Flow
1. **Preview Request**
   - `GET /api/v1/cbl-lists/{list_id}/preview`
   - Load `CBLSourceList` and validate ownership/permissions
   - Load `CBLSourceEntry` sorted by `position`
   - Call `reconcile_cbl_source_list` for each entry
   - Build `CBLPreviewResponse` preserving order and state

2. **Plan Calculation**
   - `POST /api/v1/cbl-lists/{list_id}/calculate-plan`
   - Apply reader decisions:
     - Apply series-level decisions first
     - Apply individual entry decisions (can override series)
     - Respect the rule: excluding a series excludes all entries, unless overridden
   - Generate plan with:
     - Adopted entries (existing + missing to create)
     - Excluded entries (tracked for user reference)
     - Unresolved entries (preserved for potential later resolution)
     - Source-backed order with original positions preserved

## Testing requirements

### Unit tests (`tests/test_cbl_adoption.py`)

1. **Exact ComicVine-backed existing issue reuse**
   - CBL entry with ComicVine ID resolves to correct canonical issue
   - Read status, rating, and events preserved
   - No new issues created

2. **Legacy/history-preserving canonical reconciliation**
   - Title/issue number only entries use existing reconciliation logic
   - Ambiguous entries surfaced without being dropped
   - Duplicate identities handled correctly

3. **Missing entry appears as a candidate**
   - Missing entry marked as "pending creation"
   - ComicVine search/comicvine-hydration paths respected
   - No physical issue created during preview

4. **Ambiguous entry remains visible**
   - Entries without ComicVine ID marked as ambiguous
   - Available for reader confirmation in UI
   - Preserved across plan calculations

5. **Whole-series exclusion removes both existing and missing entries**
   - Series-level "exclude" decision applied to all positions
   - Both existing and missing entries excluded from plan
   - Series exclusion can be overridden per entry

6. **Individual override works**
   - Single entry can be included even when its series is excluded
   - Override decisions recorded separately
   - Source-backed order includes overridden entries

7. **Skipped positions retain source-position gaps**
   - Excluded positions preserve their original numeric position
   - Source-backed order may have gaps (no renumbering)
   - Adoption reflects exact reader choices

8. **Preview/plan leaves counts for issues, threads, memberships unchanged**
   - Verify database state after preview/plan calculations
   - No threads, issues, memberships, dependencies created
   - Atomicity of plan calculations preserved

9. **No `cbl-order:source:*` rows produced**
   - Verify plan calculations don't create legacy dependencies
   - Source-backed adoption uses canonical ordered representation
   - Compatibility with future source-backed roll behavior

10. **User-provided `.cbl` file parsing boundary**
    - If infrastructure can parse `.cbl` files, include read-only path
    - Otherwise, document the remaining boundary for frontend to handle
    - Reuse the normalized preview representation from endpoint

## Risks and mitigation

### High risk: Contract boundary ambiguity
**Risk**: Unclear separation between preview/plan and commit paths
**Mitigation**: Strict API contract, reusable decision types, clear "dry-run" semantics

### Medium risk: Performance with large CBL lists
**Risk**: Large lists (e.g., Ultimate Universe's 130 entries) may be slow
**Mitigation**: Use efficient queries, consider pagination for very large lists

### Low risk: Integration with existing reconciliation
**Risk**: Edge cases in existing reconciliation not handled
**Mitigation**: Extensive testing, reuse existing trust mechanisms
