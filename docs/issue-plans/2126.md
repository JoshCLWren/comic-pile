# Issue Plan: #2126 — CBL Adoption Preview + Adoption-Plan API

## Context

Parent: #1615 (CBL browser, selective import, reconciliation, source-backed reading-order workflow).
This is Child A: backend read-only preview/planning layer for one CBL source list.

## Current state

- `app/cbl_ingest.py` parses `.cbl` files into `CBLList`/`CBLBook` (pure, no DB I/O).
- `app/cbl_sync.py` persists parsed lists into `cbl_sources`, `cbl_source_lists`, `cbl_source_entries`.
- `app/services/cbl_reconciliation.py` `reconcile_cbl_source_list(db, user_id, list_id)` returns a `CBLReconciliationReport` with per-position canonical resolution + read state.
- `app/services/issue_identity_reconciliation.py` `resolve_cbl_entries_to_canonical` resolves CBL entries to canonical Issue IDs using ComicVine evidence.
- `app/api/issue_identity.py` has `GET /api/v1/issue-identity/cbl/{list_id}/reconciliation` — returns the raw report dict.

## What's missing

The issue requires:
1. A structured preview API returning per-entry state (existing canonical issue with read status, missing/importable, ambiguous, source metadata/provenance).
2. Stable series/run grouping keys so UI can apply whole-series decisions.
3. A pure/adoption-plan calculation that accepts proposed decisions and returns a mutation summary without performing mutations.
4. Decision semantics: include/exclude one entry, include/exclude whole series/run, individual override of series-level choice.
5. Excluding an entry works even when the comic already exists.
6. Adopted entries preserve original CBL positions; gaps allowed.
7. Mutation summary: existing issues reused, missing issues that would be created, excluded entries, unresolved/skipped entries, final adopted count/order.
8. Zero mutations: no threads, issues, memberships, continuity rules, dependencies, or read-history changes.
9. No `cbl-order:source:*` dependency rows.
10. User-provided `.cbl` normalization path (read-only, no persistence) if feasible.

## Implementation plan

### 1. Schemas (`app/schemas/cbl_adoption.py`)

- `CBLPreviewEntry` — one source position with canonical resolution + read state + series/run grouping keys.
- `CBLPreviewResponse` — full preview with source metadata, series/run groups, entries.
- `CBLAdoptionDecision` — a decision on one entry or series (include/exclude/override).
- `CBLAdoptionPlanRequest` — the full set of decisions applied to a source list.
- `CBLMutationSummary` — the read-only mutation summary.

### 2. Service (`app/services/cbl_adoption.py`)

- `preview_cbl_source_list(db, user_id, list_id) -> CBLPreviewResponse` — builds on `reconcile_cbl_source_list`, adds series/run grouping keys.
- `calculate_adoption_plan(db, user_id, list_id, decisions) -> CBLMutationSummary` — pure/read-only, applies decisions to the preview and computes the mutation summary.
- Series/run grouping: use `series_name` + `volume_year` as the run key (from `CBLSourceEntry`).

### 3. Router (`app/api/cbl_adoption.py`)

- `GET /api/v1/cbl-adoption/{list_id}/preview` — authenticated, read-only preview.
- `POST /api/v1/cbl-adoption/{list_id}/plan` — authenticated, read-only adoption plan.

### 4. Registration

- Register router in `app/main.py` under `/api/v1/cbl-adoption`.

### 5. Tests (`tests/test_cbl_adoption.py`)

Cover all 9 test scenarios from the issue:
1. Exact ComicVine-backed existing issue reuse.
2. Legacy/history-preserving canonical reconciliation.
3. Missing entry appears as candidate, no comic created.
4. Ambiguous entry remains visible.
5. Whole-series exclusion removes both existing and missing entries.
6. Individual override can re-include one entry from excluded series.
7. Skipped positions retain source-position gaps.
8. Preview/plan leaves counts for issues, threads, memberships, dependencies unchanged.
9. No `cbl-order:source:*` rows produced.

## Risks

- Must not mutate any state — tests will assert counts unchanged.
- Series/run grouping must be stable and derivable from CBL source data.
- The adoption plan calculation must be pure (no DB writes).

## Rollback

Remove the new schema/service/router files and revert `app/main.py` registration. No DB migrations needed.
