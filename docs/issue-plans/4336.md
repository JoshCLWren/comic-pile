### Route Mapping (vercel.json) — corrected 2026-11-04 (Factory 46)

**Verified against `vercel.json` (51 explicit route entries; full file read at `vercel.json:296-310`).**
The plan's earlier claim that skip/dismiss routes were routed to Rust was **wrong**. The only
roll routes explicitly routed to `api/native_roll.rs` in `vercel.json` are:

| Path | Methods | Dest |
| --- | --- | --- |
| `/api/v2/roll/bootstrap` | GET | `/api/native_roll.rs` |
| `/api/v2/roll/dice-command` | POST | `/api/native_roll.rs` |
| `/api/v2/roll/offer` | POST | `/api/native_roll.rs` |
| `/api/v2/roll/reset` | POST | `/api/native_roll.rs` |
| `/api/v1/roll/dismiss-pending` | POST | `/api/native_roll.rs` |
| `/api/roll/dismiss-pending` | POST | `/api/native_roll.rs` |

**There is NO explicit route for `/api/v1/roll/skip` or `/api/roll/skip`.** Both fall through to
the catch-all route at `vercel.json:332`:

```json
{ "src": "/api(?:/.*)?", "dest": "/api/index.py" }
```

So `POST /api/v1/roll/skip` and `POST /api/roll/skip` are served by the **Python** FastAPI app
(`api/index.py` → `app/api/roll.py:389 skip_roll`), **not** by Rust. The Rust module
`native/roll-service/src/skip.rs` registers the same paths internally
(`lib.rs:259-260`) but that registration is dead in production because Vercel never routes
those paths to `api/native_roll.rs`. The Rust skip handler has **never** been live.

`POST /api/v1/roll/` (the core roll mutation this issue retires) is likewise served by Python
(`app/api/roll.py:242 roll_dice`), not Rust. The Rust `roll_offer` handler is reachable only
via the explicitly routed `/api/v2/roll/offer` (`vercel.json:241`).
