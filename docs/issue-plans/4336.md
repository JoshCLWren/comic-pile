# Issue 4336 Plan: Migrate retiring v1 Roll mutation in favor of sessionless Rust v2 resources

## Owner-Approved Final Contract (2026-10-31)

**Final destination:** Rust resource-oriented v2 Roll/offer event flow governed by #4405

The separate legacy Python Roll/session mutation and its session persistence must not be reimplemented for its own sake. Preserve real Roll/reroll outcomes, die transitions, client recovery, and event history as specified by #4405. Coordinate with existing Rust v2 offer/dice-command/reset routes; migrate every real caller, remove v1 aliases and Python session-only code.

## Current State Analysis

### Python v1 Roll Mutation
- **Endpoint**: `POST /api/v1/roll/` (app/api/roll.py:240)
- **Handler**: `roll_dice()` function
- **Features**:
  - Creates a ReadingSession if none exists
  - Validates no pending roll
  - Selects thread using weighted bounded-pool selection
  - Records Event and RecommendationContext
  - Sets pending_thread_id on session
  - Returns RollResponse

### Route Mapping (vercel.json) — corrected 2026-11-04 (Factory 46)

**Verified against `vercel.json` (51 explicit route entries; full file read at `vercel.json:296-310`).**
The plan's earlier claim that skip/dismiss routes were routed to Rust was **wrong**. The only
roll routes explicitly routed to `api/native_roll.rs` in `vercel.json` are:

| Path | Methods | Dest |
| --- | --- | --- |
| `/api/v2/roll/bootstrap` | GET | `/api/native_roll.rs` |
| `/api/v2/roll/dice-command` | POST | `/api/native_roll.rs` |
| `/api/v2/roll/offer` | POST | `/api/native_roll.rs` |
| `/api/v2/roll/reset` | POST | `/api/native_roll.rs` |
| `/api/v1/roll/dismiss-pending` | POST | `/api/native_roll.rs` |
| `/api/roll/dismiss-pending` | POST | `/api/native_roll.rs` |

**There is NO explicit route for `/api/v1/roll/skip` or `/api/roll/skip`.** Both fall through to
the catch-all route at `vercel.json:332`:

```json
{ "src": "/api(?:/.*)?", "dest": "/api/index.py" }
```

So `POST /api/v1/roll/skip` and `POST /api/roll/skip` are served by the **Python** FastAPI app
(`api/index.py` → `app/api/roll.py:389 skip_roll`), **not** by Rust. The Rust module
`native/roll-service/src/skip.rs` registers the same paths internally
(`lib.rs:259-260`) but that registration is dead in production because Vercel never routes
those paths to `api/native_roll.rs`. The Rust skip handler has **never** been live.

`POST /api/v1/roll/` (the core roll mutation this issue retires) is likewise served by Python
(`app/api/roll.py:242 roll_dice`), not Rust. The Rust `roll_offer` handler is reachable only
via the explicitly routed `/api/v2/roll/offer` (`vercel.json:241`).

### Key Observations (corrected 2026-11-04)

1. The Rust v2 service **already implements** skip, dismiss-pending, offer, dice-command and
   reset handlers in `native/roll-service/src/`, and the Rust crate compiles cleanly
   (`cargo check` green at this head).
2. **Only dismiss-pending is actually live in Rust.** Of the Rust roll handlers, only
   `/api/v1/roll/dismiss-pending` and `/api/roll/dismiss-pending` have explicit
   `vercel.json` routes to `api/native_roll.rs`. Skip, offer, dice-command and reset are
   either unrouted (skip) or routed (offer/dice-command/reset) — see the corrected table above.
3. The v1 Python `roll_dice()` endpoint (`POST /api/v1/roll/`) is served by Python
   (`app/api/roll.py:242`) and is **not** routed to Rust. No Rust handler exists for it.
4. The Rust v2 flow is **sessionless** - it doesn't create ReadingSessions like the Python v1
   version. The Rust `reading_session.rs` module is internal only; `bootstrap_v2` /
   `initialize_session` are reachable only via the explicitly routed
   `/api/v2/roll/bootstrap` and `/api/v2/reading-sessions` paths.
5. The issue is about **retiring the Python v1 mutation**, not reimplementing it.
