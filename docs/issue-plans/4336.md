# Issue 4336 Plan: Migrate retiring v1 Roll mutation in favor of sessionless Rust v2 resources

## Owner-Approved Final Contract (2026-10-31)

**Final destination:** Rust resource-oriented v2 Roll/offer event flow governed by #4405

The separate legacy Python Roll/session mutation and its session persistence must not be reimplemented for its own sake. Preserve real Roll/reroll outcomes, die transitions, client recovery, and event history as specified by #4405. Coordinate with existing Rust v2 offer/dice-command/reset routes; migrate every real caller, remove v1 aliases and Python session-only code.

## Acceptance Criteria

- [ ] Inventory the exact frontend, retry/recovery, automation and external supported consumers and their currently deployed routes.
- [ ] Deliver the approved Rust v2 resource and update real consumers together, preserving authentication/ownership, visible results, errors, idempotency and concurrency.
- [ ] Exactly **one issued SQL statement per DB-backed request**, including auth; measure actual DB bytes/CPU, network, Rust CPU/wall and Fluid Compute. No costly hidden JSONB snapshots, per-row N+1 or duplicated screen requests.

- [ ] Delete the **specific old Python/v1 handlers, frontend callers, obsolete generated types, schema bindings, tests and exclusive helpers** once the replacement is deployed and verified; do not leave v1 aliases or dead parallel Rust ports.
- [ ] Require exact-head green CI, independent semantic review (Greptile optional), and authenticated real production verification before closure.

## Current State Analysis

### Python v1 Roll Mutation
- **Endpoint**: `POST /api/v1/roll/` (app/api/roll.py:240)
- **Handler**: `roll_dice()` function
- **Features**:
  - Creates a ReadingSession if none exists
  - Validates no pending roll
  - Selects thread using weighted bounded-pool selection
  - Records Event and RecommendationContext
  - Sets pending_thread_id on session
  - Returns RollResponse

### Rust v2 Resource-Oriented Flow
- **Endpoints**:
  - `/api/v2/roll/dice-command` (POST) - manual die input (native/roll-service/src/dice_api.rs)
  - `/api/v2/roll/offer` (POST) - sessionless offer event (native/roll-service/src/roll_offer.rs)
  - `/api/v2/roll/reset` (POST) - reset die (native/roll-service/src/roll_reset.rs)
  - `/api/v1/roll/skip` (POST) - skip endpoint (native/roll-service/src/skip.rs)
  - `/api/roll/skip` (POST) - skip endpoint alias
  - `/api/v1/roll/dismiss-pending` (POST) - dismiss pending (native/roll-service/src/dismiss_pending.rs)
  - `/api/roll/dismiss-pending` (POST) - dismiss pending alias

### Route Mapping (vercel.json)
- `/api/v1/roll/skip` → `/api/native_roll.rs` (Rust v2)
- `/api/roll/skip` → `/api/native_roll.rs` (Rust v2)
- `/api/v1/roll/dismiss-pending` → `/api/native_roll.rs` (Rust v2)
- `/api/roll/dismiss-pending` → `/api/native_roll.rs` (Rust v2)

### Frontend Consumers
- `frontend/src/services/protectedRollMutationApi.ts`:
  - `skip: POST /v1/roll/skip` (line 22)
  - Uses `RECOVERY_CONFIG` for retry/recovery
- `frontend/src/test/reading-mode-acceptance.spec.ts`:
  - Tests reading mode with Roll operations
- `frontend/src/unit/rollSkipSingleRefresh.test.tsx`:
  - Unit tests for skip refresh
- `frontend/src/unit/rollSnoozeSingleRefresh.test.tsx`:
  - Unit tests for snooze refresh

### Key Observations
1. The Rust v2 service **already implements** the skip and dismiss-pending endpoints
2. The v1 Python `roll_dice()` endpoint (`POST /api/v1/roll/`) is NOT currently routed to Rust
3. The Rust v2 flow is **sessionless** - it doesn't create ReadingSessions like the Python v1 version
4. The issue is about **retiring the Python v1 mutation**, not reimplementing it
