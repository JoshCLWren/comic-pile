# Issue #1734: Phase 5 reading-mode UI acceptance regression

## Goal

Prove the first user-visible reading-mode workflow is coherent, accessible, and does not add unnecessary friction.

## Acceptance Criteria

- [x] Roll header shows the canonical active bandwidth + intent.
- [x] User can manually switch bandwidth and intent and subsequent rolls use the updated mode.
- [x] Random intent activates the legacy unweighted control path.
- [x] A normal Snooze does not automatically interrupt with a modal.
- [x] Repeated/meaningful mismatch can show the correction sheet and its choices update canonical session state.
- [x] Refresh/reload restores state from bootstrap rather than a second frontend cache.
- [x] Focused Chromium/rendered coverage verifies keyboard, mobile, and desktop behavior.

## What was built

### 1. ModeSelectorSheet component (`frontend/src/components/ModeSelectorSheet.tsx`)

New modal/bottom sheet with two independent radio groups:
- **Bandwidth:** Light · Balanced · Deep
- **Intent:** Balanced · Momentum · Familiar · Explore · Random

Features:
- Submits through canonical `sessionsApi.updateMode()` PATCH endpoint
- Shows active values from bootstrap
- Changing one dimension does not reset the other
- Random intent shows description: "Unweighted legacy-style selection within the current die pool"
- Keyboard accessible (Enter to select, Escape to close)
- Mobile bottom-sheet, desktop centered modal via shared `Modal` component
- Error state on API failure
- Disables options during submission

### 2. RollPage integration (`frontend/src/pages/RollPage/index.tsx`)

- Added `isModeSelectorOpen` state
- Added `handleModeSelectorSubmit` callback that calls `sessionApi.updateMode()` and refetches bootstrap
- Wired `onOpenModeSelector` prop to `RollHeader`
- Rendered `ModeSelectorSheet` with bootstrap session mode data

### 3. CorrectionSheet unit test (`frontend/src/unit/CorrectionSheet.test.tsx`)

13 tests covering:
- Renders nothing when closed
- Shows all five correction choices
- Submits correct patch for each choice
- Dismiss closes without submitting
- Error state on submit failure
- Disables choices while submitting
- Keyboard accessibility

### 4. ModeSelectorSheet unit test (`frontend/src/unit/ModeSelectorSheet.test.tsx`)

9 tests covering:
- Renders nothing when closed
- Renders both radio groups
- Shows active values as selected
- Submits bandwidth-only patch
- Submits intent-only patch
- Defaults to balanced when no mode
- Error state on submit failure
- Shows Random intent description
- Disables options while submitting
- Closes on Escape

### 5. E2E acceptance test (`frontend/src/test/reading-mode-acceptance.spec.ts`)

11 Chromium tests covering all acceptance criteria:
- Roll header displays canonical bandwidth/intent from bootstrap
- Manual bandwidth switch takes effect
- Manual intent switch takes effect
- Random intent activates unweighted path
- Normal snooze doesn't auto-interrupt with modal
- Mode selector shows Random with unweighted description
- Refresh/reload restores state from bootstrap
- Keyboard accessibility (Enter to select)
- Escape closes without changing state
- Mobile viewport works
- Mode control doesn't dominate header visually
