## Implementation Details

### Rust v2 Endpoint Structure

**Route:** `GET /api/v2/continuity-plans/{plan_id}/reader`

**Authentication:** Same as Python - JWT Bearer token

**Response schema:** Match Python `ReadingPlanReaderResponse` exactly

**Database queries:** One SQL statement per request including auth

**Error handling:** Match Python behavior (404 for unauthorized/not found)

### Key Implementation Considerations

1. **Option E vs Legacy mode:**
   - Option E: Use linked reading list for authoritative order
   - Legacy: Use plan's own order
   - Must preserve both modes

2. **Source provenance:**
   - Preserve source_paths, source_names, repository info
   - Maintain adoption tracking

3. **Blocking logic:**
   - Preserve blocker calculation for legacy mode
   - Use reading list's blocking for Option E

4. **Release sources:**
   - List release sources for reader
   - List release candidates for reader

### Testing Strategy

1. **Unit tests:** Rust module tests for service logic
2. **Integration tests:** Test against real database
3. **E2E tests:** Frontend tests using v2 endpoint
4. **Regression tests:** Verify no behavior changes
